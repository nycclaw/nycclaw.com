What Claude Cowork Plugins Actually Are

A plugin is a bundle of everything Claude needs to do a specific job well. Each one packages together skills (domain knowledge Claude draws on automatically), connectors (links to tools like Slack, HubSpot, or Jira), slash commands (explicit actions you trigger), and sub-agents (specialized AI helpers for specific tasks).

Plugins are just files. Markdown and JSON. No code, no infrastructure, no build steps. You can read every instruction a plugin gives Claude, edit it, or write your own from scratch. This is what makes Cowork plugins different from traditional software extensions. They're transparent and editable.

Without a plugin, Claude Cowork is a general assistant. With the right plugin installed, it becomes a sales rep who knows your CRM, a support agent who follows your escalation rules, or a finance analyst who runs your reconciliation workflow. The plugin tells Claude what to do, how to do it, and which tools to use.

Plugin Architecture: How They're Built

Every plugin follows the same directory structure. Once you understand it, you can read, modify, or build any plugin.

plugin-name/
├── .claude-plugin/plugin.json   # Manifest: name, version, description
├── .mcp.json                    # Connector configs (MCP servers)
├── commands/                    # Slash commands you trigger manually
├── skills/                      # Domain knowledge Claude uses automatically
├── agents/                      # Specialized sub-agents for complex tasks
└── hooks/                       # Event handlers (runs on specific triggers)

plugin.json

The manifest file. Contains the plugin's name, version, description, and metadata. This is what shows up in the marketplace when someone browses for plugins.

.mcp.json

Connector configurations. This file tells Claude which external tools to connect to via the Model Context Protocol. Each connector entry specifies how to authenticate and communicate with a tool like Slack, Notion, or Snowflake.

commands/

Slash commands are actions you trigger explicitly. For example, /sales:call-prep or /finance:reconciliation. Each command is a markdown file with step-by-step instructions Claude follows when you invoke it.

skills/

SKILL.md files that give Claude domain expertise. Unlike commands, skills fire automatically when Claude detects they're relevant. A contract review skill activates when you drop a contract into the conversation. Read more about skills.

agents/

Sub-agents are specialized AI helpers with their own context, tools, and permissions. A plugin might include a research agent that only reads data, or a triage agent that sorts incoming tickets. Claude invokes them automatically based on the task.

hooks/

Event handlers that run on specific triggers. A hook might auto-format documents after Claude writes them, or validate data before Claude sends it to a connector. Events include PreToolUse, PostToolUse, SessionStart, TaskCompleted, and more.

The Plugin Marketplace

The 11 official plugins are just the starting point. Claude Cowork has a marketplace of plugins built by Anthropic, third-party companies, and the community.

Official Marketplace

The claude-plugins-official marketplace is built into Claude Cowork. Browse it by typing /plugin and selecting the Discover tab. Install any plugin with one click, or use the command /plugin install plugin-name@claude-plugins-official. You can also submit your own plugins for inclusion at claude.ai/settings/plugins/submit.

External Integration Plugins

Beyond the 11 official role-based plugins, there are integration plugins for specific platforms:

GitHub GitLab Figma Slack Atlassian (Jira/Confluence) Asana Linear Notion Vercel Firebase Supabase Sentry

Custom Marketplaces

Any GitHub repo, Git URL, or local directory can serve as a plugin marketplace. Add one with /plugin marketplace add owner/repo. This is useful for teams that build internal plugins and want a centralized place to browse and install them.

Building Custom Plugins

The official plugins cover common roles. But your business isn't generic. Custom plugins encode the workflows, terminology, and tools specific to your business into something Claude follows every time.

Start from Scratch

Install the Plugin Create plugin and describe what you need. It generates the full directory structure: plugin.json, .mcp.json, commands, skills, agents, and hooks. You fill in the details. Since everything is markdown and JSON, you don't need a developer to maintain it.

Fork an Official Plugin

All 11 official plugins are open source at github.com/anthropics/knowledge-work-plugins. Fork the one closest to your role, then customize it. Swap connectors in .mcp.json, add company-specific skill files, modify command workflows, or remove things you don't need.

Installation Scopes

Plugins can be installed at four levels, each with a different reach:

Scope Settings File Use Case
User ~/.claude/settings.json Personal use across all projects
Project .claude/settings.json Team-wide, shared via git
Local .claude/settings.local.json Project-specific, gitignored
Managed Enterprise settings Org-wide, read-only for members

A real estate team might fork the Productivity plugin and add skills for listing descriptions, comp analysis, and client follow-up. A law firm might start with the Legal plugin and add skills encoding their specific contract review checklist and citation formatting rules. The setup guide covers the full process.

Organization Marketplaces for Teams

On Team and Enterprise plans, organization owners can create curated plugin marketplaces for their members. This gives you control over which plugins your team uses and how they're distributed.

Auto-Install

Plugin installs automatically for every member. Use this for must-have plugins that encode company standards.

Available

Plugin is visible in the marketplace but optional. Members install it if it's relevant to their role.

Hidden

Plugin exists in the org marketplace but isn't shown to members. Useful for plugins still in testing.

Manage all of this through Organization settings, in the Plugins section. For details on Cowork plan options, see the pricing guide.

Frequently Asked Questions

What are Claude Cowork plugins?
Claude Cowork plugins are bundles of skills, connectors, slash commands, and sub-agents packaged together for a specific role or workflow. They're file-based, built with markdown and JSON, and require no coding. Anthropic offers 11 official plugins covering roles like Sales, Legal, Finance, Marketing, and more.
How do I install a Claude Cowork plugin?
Open a Cowork session, type /plugin, and browse the Discover tab. Select a plugin and click install. You can also install from the command line with /plugin install plugin-name@claude-plugins-official. Plugins can be scoped to a single user, a project, or an entire organization.
Can I build my own Claude Cowork plugin?
Yes. You can build a plugin from scratch using the Plugin Create plugin, or fork any of the 11 official plugins from Anthropic's GitHub repository at github.com/anthropics/knowledge-work-plugins. Plugins are just markdown and JSON files in a specific directory structure, so no programming is required.
What's the difference between plugins and skills?
A skill is a single SKILL.md file that teaches Claude one capability or workflow. A plugin is a complete package that bundles multiple skills together with connectors, slash commands, sub-agents, and hooks. Think of skills as individual tools and plugins as full toolboxes for a specific role. Learn more on the skills page.
Can my company create a private plugin marketplace?
Yes. On Team and Enterprise plans, organization owners can create curated plugin marketplaces. You set per-plugin installation preferences: auto-install for all members, available for optional install, or hidden. This is managed through Organization settings in the Plugins section.
